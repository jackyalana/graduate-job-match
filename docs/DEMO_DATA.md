# 虚构演示数据

仓库内的 `scripts/delivery/chinese_demo.py` 包含可生成的中文虚构数据，不包含数据库导出、真实简历、账号密码或访问令牌。它通过项目本机 demo 的业务接口创建岗位、技能、画像、简历、投递及状态事件，并记录浏览、收藏和隐藏；匹配分由现有后端算法计算。默认使用本地运行年度生成毕业年份和有效期。

## 准备与导入

1. 克隆 `delivery/final` 分支。在 macOS Apple Silicon 上，先按 [基线说明中的新检出准备步骤](BASELINE.md) 准备项目私有的 JDK、Maven、MySQL、依赖和 `.local` 凭据；运行环境只用于虚构数据，不要连接真实业务库。该工具安装流程尚未在第二台空机器验收。
2. 按 [交付报告的启动步骤](DELIVERY_REPORT.md#启动与演示) 新建隔离演示库、构建并启动服务。若服务已经在运行，不需要重建库或重复执行启动命令。初始化脚本只接受 `.local/m1-schemas.json` 中的项目运行库及相应的 18081 端口后端。
3. 在项目根目录执行：

   ```bash
   python3 scripts/delivery/chinese_demo.py
   ```

   按提示输入自己设置的演示密码。脚本会把该密码用于五个已有演示账号（`demo_admin`、`demo_student`、`demo_student2`、`demo_hr`、`demo_hr2`）及新增的演示账号；会改变这五个账号的原密码，但不修改其他现有账号密码。旧密码哈希保存在 Git 忽略的项目私有 `.local/` 中，不要分享该目录。非交互场景也可通过本地环境变量 `DELIVERY_DEMO_PASSWORD` 传入，不要把密码写入源代码或日志。
4. 打开 <http://127.0.0.1:15174/>，选择用户名密码登录。三角色入口分别是 `demo_student`、`demo_hr`、`demo_admin`，密码为第 3 步自行输入的值。

## 数据与重复执行

在初始演示库中，脚本会生成 6 家新虚构企业及 18 名新虚构学生，加上已有的 2 家演示企业和 2 名演示学生，合计 8 家企业和 20 名学生；创建 50 个岗位及约 60 条不同阶段的投递，附带行为记录。部分岗位待审核或已关闭。学生可以浏览推荐并继续投递，HR 可处理申请，管理员可查看待审岗位和统计。脚本会实际提交一次演示投递用于验证，不代表真实招聘行为。

脚本在 `.local/` 按数据库记录执行进度，运行完成后再次运行会直接退出，避免重复插入或覆盖后续操作。中断后可用相同密码重试；首次执行若发现 `zhdemo_` 同名账号或同名既有岗位，会停止以避免覆盖已有数据。若之后手动删除数据，完成标记不会自动补回；若要重新生成，应使用新建的隔离演示库，而不是删除当前用户的数据或随意删除进度文件。

本机已有演示库已实际导入并验证；当前重新执行验证为无重复写入。脚本的新机器完整安装和全新库首次导入仍需在目标机器验证。
