# 系统审核与验收清单

审核对象是固定提交和实际运行结果。实施 AI 的描述、README、截图、模拟测试及 health 接口各自只能证明对应层面，不能互相替代。

## 1 审核输入与判定

实施者每次提供阶段、仓库或绝对路径、commit SHA、diff、运行环境、执行命令、退出码、测试与页面证据、未完成项。审核者先读取当前状态，核实证据与待审版本一致；不根据旧提交或缓存分支作通过判断。

判定只有“通过”“需修改”“阻塞”。未获取代码或无法运行时说明阻塞点，可先进行静态审查但不签发运行通过。P0 为数据泄露、破坏数据、认证失效等阻断问题；P1 为核心业务、算法或验收错误；P2 为不阻断主流程的问题。P0/P1 清零且阶段门槛满足后通过。

审核默认只读，不把检查请求自动解释为部署、推送、合并或生产数据操作。隔离测试库和演示环境由阶段交付提供。

## 2 M0 底座准入

- [ ] 上游 URL、完整 SHA、许可证与本地源码一致。
- [ ] Java/Maven/Node/MySQL 版本和锁文件记录完整。
- [ ] 没有执行未知远程脚本、连真实数据库或发送真实邮件。
- [ ] 后端测试和前端 build 实际执行；失败、跳过、修复均有证据。
- [ ] 三角色登录、岗位审核、简历保存、匹配和投递至少完成一次真实冒烟，或明确哪项失败及其影响。
- [ ] 分清原项目缺陷与本课题新增需求。
- [ ] 复用矩阵和 API 映射能解释保留、改造和新增范围。
- [ ] 技术版本路线明确，未把源码可读等同于可直接交付。

## 3 M1 数据与权限

- [ ] 迁移能在空库初始化，也能从锁定上游 schema 增量执行；重复运行行为明确。
- [ ] user_id、hr_id 从会话取得；客户端篡改归属无效。
- [ ] 学生跨用户、HR 跨企业的读写和下载被拒绝。
- [ ] 注册不能创建 ADMIN；禁用账号的旧令牌不可继续使用。
- [ ] 企业和岗位审批不能由提交者自行写入通过状态。
- [ ] 待审、下架、过期和企业禁用的岗位在详情、搜索、推荐、投递四处表现一致。
- [ ] 敏感字段不在 API 或日志泄露；旧接口不绕过新规则。

## 4 M2 算法正确性

| 测试编号 | 固定场景 | 期望 |
| --- | --- | --- |
| ALG01 | 相同非零技能向量，熟练度满足 | cosine=1、coverage=1、skill=1 |
| ALG02 | 双方已填技能但完全无交集 | skill=0，不能当缺失维度跳过 |
| ALG03 | 学生或岗位未填写技能 | skill unavailable，剩余维度重归一 |
| ALG04 | 四维为 0.8/1/1/0.5 | C=0.825，matchScore=82.5 |
| ALG05 | ALG04 且无邻居，H=0.4 | R=0.74，recommendationScore=74.0 |
| ALG06 | 全部匹配维度缺失且无邻居 | matchScore=null、R=H、HOT_FALLBACK |
| ALG07 | 学历不足/毕业年不符合/已过期 | 不进入个性化候选；不能被热门兜底补回 |
| ALG08 | 第 201 个及更早岗位最匹配 | 仍能进入推荐前列，不受上游最新 200 限制 |
| ALG09 | 已投递或 HIDE | 不推荐；取消 HIDE 后可以恢复 |
| ALG10 | 改画像、技能要求或算法版本 | 旧缓存/批次不可当新结果使用 |
| ALG11 | 多项分数相同 | 按明确并列规则稳定排序 |
| ALG12 | 不足 K、无候选、无有效邻居 | 返回真实数量和明确原因，不报 NaN 或伪造记录 |

还要检查每条 reason 与实际维度对应，分数可由 components 和 effectiveWeights 重算，前端不进行第二套评分；推荐卡不把排序分当录用概率。

## 5 M3 招聘闭环与隐私

- [ ] 学生用不同简历并发投同岗位，数据库最终只留一条投递。
- [ ] 岗位关闭和投递竞争时按事务规则串行判定，关闭后无新投递。
- [ ] 投递后修改简历或岗位，不改历史快照。
- [ ] 岗位和简历归档不丢失投递、事件和有效文件引用。
- [ ] 每个允许与不允许的状态转移均覆盖；并发更新返回 409。
- [ ] HR 不可自己把学生改为 ACCEPTED；学生不能替企业发 OFFERED。
- [ ] 文件大小、类型、路径穿越和跨账号下载有测试；附件没有公开裸链接。
- [ ] 三角色真实浏览器流程完成；重新启动和刷新后数据仍存在。
- [ ] 所有列表有加载、空状态和失败状态；手机与桌面关键页面可操作。
- [ ] 管理统计可由数据库查询复核，“录用接受”没有被写成实际就业率。

## 6 M4 实验和最终交付

- [ ] 数据来源、合成标识、随机种子、样本数、时间边界与文件哈希完整。
- [ ] 测试反馈没有流入 CF、热度、画像或候选生成；取消事件按时间重放。
- [ ] 热门、内容、混合算法使用相同候选规则、K 和相关标签。
- [ ] 指标分母明确，无有效样本时显示不可评估而不是“100%”。
- [ ] 评估调用的算法与线上一致；关键固定输入输出有一致性验证。
- [ ] 记录真实数值，无收益时保留结果与原因，不反向改数据。
- [ ] 关键 SQL、唯一键和事务测试在 MySQL 上执行；仅 H2 或 Mockito 不算数据库通过。
- [ ] 性能环境、数据规模、并发、预热、P95 与错误率可重跑。
- [ ] 全新机器按文档可启动；Compose/本机命令经过实际验证，不能只提供未跑过模板。
- [ ] 提供 LICENSE、THIRD_PARTY_NOTICES、源码、增量 SQL、合成数据脚本、测试、评估、截图和演示步骤。
- [ ] 所有实际执行的命令和证据能对应最终 SHA；没有“后端已通过但又改过未测”的空档。

## 7 反馈格式

每条问题写清：严重程度、文件及行号、触发条件、当前行为、期望行为、最小复现或验证步骤。只报告有依据的问题；将“已确认缺陷”和“需要补充证据”分开。

实施 AI 修复后提交新 SHA 与针对性回归。审核者重新读取相关 diff、复现修复并检查受影响主流程，不因它回复“已修复”而自动关闭问题。
