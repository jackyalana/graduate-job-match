# 合成推荐实验

在项目根目录先按交付报告构建后端，再运行 `python3 scripts/delivery/evaluate.py`。脚本调用后端同一套内容、协同过滤和融合计算类，两次生成并逐字比较；输出在 `output/synthetic-20261027/`，包括 JSON、CSV 和含源码提交与数据哈希的 manifest。

数据由固定 seed=20261027 生成：60 个合成用户、80 个合成岗位、250 条训练行为、60 条保留但不用于计算的验证行为和 120 条测试行为。时间轴按 70/15/15 分段；测试正反馈不进入用户向量、热度及候选过滤。训练中没有行为的 10 个用户单独报告。所有岗位视为发布且合格，已训练投递岗位从候选中排除。

三种方法在相同用户及候选集合上比较：HOT 使用热度、CONTENT 使用内容维度、HYBRID 使用系统融合与冷启动回退。纯 CONTENT 基线在内容不可用时按相同零排序键及岗位 ID 排列，仅用于可比较的实验，不改变应用中匹配分为 null 的规则。评价为 Precision、Recall、NDCG、HitRate 的 @5 和 @10，以及 Coverage@10 和回退比例。合成潜在偏好与岗位类别有意相关，因此较高的内容指标不能作为真实世界效果或泛化证据。
